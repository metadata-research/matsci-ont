# ChEBI CORE 254: import and source identity

Local implementation record, 2026-09-19. Host rollout is a separate phase.

## The pin and permission evidence

- [ChEBI About](https://www.ebi.ac.uk/chebi/about) states CC BY 4.0.
- [Publisher downloads](https://www.ebi.ac.uk/chebi/downloads) distinguish CORE
  (definitions and hierarchy), LITE (no definitions) and FULL (extra synonyms
  and curated cross-references).
- The immutable artifact is [release 254 CORE OWL](https://ftp.ebi.ac.uk/pub/databases/chebi/archive/rel254/ontology/chebi_core.owl).
- The artifact contains ontology IRI `http://purl.obolibrary.org/obo/chebi_core.owl`,
  version IRI `http://purl.obolibrary.org/obo/chebi/254/chebi_core.owl`, version
  `254`, date `14:08:2026 10:24`, and a CC BY 4.0 licence link. The same archive
  contains `ontology/LICENSE`.
- Uncompressed size: 362,931,373 bytes; SHA-256:
  `e0611664ee7ec7ef3ed9ce68f337af3a361dc38238e9cbce32a1ab923932bc68`.

`manifest/chebi.json` records the pin and licence evidence. Publisher IRIs
and original source triples are retained. CORE is loaded without HermiT;
the catalogue records that reasoning was skipped. Browser attribution links
the licence and publisher entity. Consumers must retain source/version and
licence attribution when presenting retrieved definitions.

## Source identity

PMD already describes ChEBI entities. On an index keyed directly by entity
IRI, multiple versions, licences and definitions become independent RDF
values and a query can combine the wrong ones. The index now has a record
per source and entity, joined to the original IRI with `ont:entity`.

Search and grounding return atomic descriptions. Exact label matches rank
ahead of broader matches, so water does not disappear behind the result
cap among thousands of water-related definitions. Entity pages and MCP's
`get_entity` accept a source key, report alternative descriptions, and use
the selected source's asserted triples and hierarchy. The same IRI is not a
new mapping: ChEBI and PMD descriptions of iron atom illustrate the shared
identifier case. A separate synthetic-store regression deliberately gives
two sources different wording, versions and licences, so matching texts in
the real ontologies cannot hide a provenance regression.

This is an index-format migration. The application and rebuilt store must
be released together; old queries that attach index fields directly to
publisher entities must follow `ont:entity` instead.

## Scale and limits

The publication build has six sources, excluding all five uncleared SAM
mirrors. ChEBI adds 3,382,033 source triples and 218,444 labelled description
records. All sources together have 222,925 descriptions. The built store is
approximately 2.2 GiB on this workstation. A complete cached/download build
finished in 2m43s with maximum resident memory about 2.4 GiB (GNU time).

Sources above 5,000 indexed entries start with at most 100 current root
classes. Their graph expands two named hierarchy levels, capped at 300 nodes
and 1,200 edges, with explicit truncation. The measured ChEBI overview has
300 nodes and 305 edges. Full content remains accessible through search,
entity lookup and SPARQL; cycles without roots are absent from the overview.
Deprecated content remains in the source snapshot and search index.

An initial whole-source property-path overview timed out. Expanding a
bounded frontier one step at a time completed on the 1 GiB development
Fuseki. Early measurements: graph JSON 14.2s, source roots 9.7s, water
lookup 2.1s. These are workstation observations, not a host latency promise.
Graph loading and failure states are visible. Large overviews start at a
readable zoom with pan/zoom controls; filtering centers a matching term. Host memory, latency and
query concurrency remain explicit release checks. In particular an
unbounded CONSTRUCT of the whole enlarged store exhausted the 1 GiB test
JVM; graph queries must be scoped and limited. The oversized-response test
now produces a >2 MiB answer from only 2,048 subjects to test the application
ceiling without using a database export as a fixture.

Database comparison now spools exports, blinds a line at a time, and sorts
on disk (64 MiB GNU sort buffer). Per-graph isomorphism remains the final
gate and still requires memory in the Jena comparison process. A second
publication build retains its publication exclusions.

## Verification record

`pnpm verify:full` passed all 43 checks. The second publication build has
identical per-graph counts and a blank-node-blinded digest beginning
`a0a51218bfccf11b` over 5,099,270 quads. All 11 nonempty named graphs are
isomorphic, including blank-node structure. The full verification/rebuild
run took 5m18s with peak resident memory about 3.7 GiB and no swap.

After the final search-ranking and UI fixes, ordinary verification passed
41 checks and the MCP client suite passed again. The manifest/index build
was unchanged after the successful deterministic comparison.

The manifest check, lint, formatting, pure tests, comparison tests,
reasoning guards, conflicting-source integration test and real MCP client
checks passed. The ChEBI checks also exercise water's exact definition,
shared-IRI source selection, atomic attribution over the entire index,
publication exclusion and bounded graph/node link integrity.

Playwright Chromium passed the browser workflow at
`http://127.0.0.1:3100`, at 1280×900 and 390×844. The Browser plugin was not
available. The checked path was catalogue → ChEBI roots → chemical entity
→ water search → definition, then iron atom ChEBI ↔ PMD, graph zoom and
filter centering, and a simulated failed graph response. Page identity,
meaningful content, absence of a framework overlay, relevant console health,
interaction state and screenshots were checked. The only console error was
the intentionally intercepted HTTP 502 in the error-state test.

Visual inspection caught and fixed mobile header/raw-table overflow and the
unreadable automatic fit of 300 nodes. The final mobile page has no document
horizontal overflow; wide RDF content scrolls within its table. Screenshots
were inspected and are kept outside the repository in /tmp. No host or
reverse-proxy deployment was exercised.
